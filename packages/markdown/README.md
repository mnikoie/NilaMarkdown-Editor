# `@tamin/markdown`

ویرایشگر و نمایشگرِ Markdown با پیش‌نمایشِ زنده، درختِ سلسله‌مراتب و
مارک‌های سفارشی — با پشتیبانیِ جدیِ فارسی و راست‌به‌چپ.

> **وضعیت: v0.1 تا v0.4 تمام‌اند** — همهٔ نقشهٔ `PROMPT.md`.
> زیر، فقط چیزی نوشته شده که **واقعاً کار می‌کند و تست دارد** — در
> مرورگرِ واقعی هم اجرا و بررسی شده (روی **بیلدِ تولیدی**، نه فقط dev)،
> نه فقط در jsdom.

## نصب و استفاده

```tsx
"use client";
import { MarkdownEditor } from "@tamin/markdown";
import "@tamin/markdown/styles.css";

// ⚠️ فقط اگر ریاضی می‌خواهید — CSSِ KaTeX **جدا** است:
import "katex/dist/katex.min.css";

<MarkdownEditor defaultValue={md} onChange={setMd} outline dir="rtl" />;
```

⚠️ **CSSِ KaTeX داخلِ `styles.css` نیست و باید خودتان import کنید.**
چون KaTeX وابستگیِ اختیاری است و اگر جاسازی‌اش کنیم، کسی که ریاضی
نمی‌خواهد هم ~۲۵ کیلوبایت و فایل‌های فونت را دانلود می‌کند.

بی آن، فرمول **خطا نمی‌دهد** ولی به‌صورتِ متنِ درهم درمی‌آید
(`i=1∑n i = 2n(n+1)` به‌جای فرمولِ درست). تستِ e2e دارد.

⚠️ **آیکون‌های نوارِ ابزار از `lucide-react` می‌آیند** — `peerDependency`ِ
اختیاری. اگر `toolbar` را روشن می‌کنید، نصبش کنید.

یا فقط لایهٔ منطق، بی UI:

```ts
import { parse, serialize, buildOutline } from "@tamin/markdown";

const doc = parse(markdown);
const tree = buildOutline(doc);
const back = serialize(doc); // === markdown
```

در Next.js: `transpilePackages: ["@tamin/markdown"]` در `next.config.ts`.
نمونهٔ کامل در `apps/web/app/markdown/page.tsx`.

مصرف‌کننده **لازم نیست Tailwind داشته باشد** — `styles.css` از قبل
کامپایل شده است.

## ساختارِ سند

فصل با `#`، ماده و تبصره با directive:

```markdown
# فصل چهارم: نحوه ارزیابی {#fasl-4}

::::ماده{شماره=۵۰ وضعیت=معتبر}
متنِ ماده

:::تبصره{شماره=۱}
متنِ تبصره
:::
::::
```

چرا این‌طور و نه همه‌چیز با `#`: [تصمیمِ ۰۰۲۲](../../docs/decisions/0022-markdown-structure-directives.md).

**حصارِ بیرونی باید بلندتر از داخلی باشد** (`::::` روی `:::`). این قاعدهٔ
CommonMark است. با `:::`ِ هم‌طول، حصارِ بستنِ اول به گرهِ داخلی نسبت داده
می‌شود و یکی سرگردان می‌ماند.

## مارکِ سفارشی

```ts
const marks = {
  نکته: {
    name: "نکته",
    label: "نکتهٔ نویسنده",
    kind: "بلوکی",
    color: "#f59e0b",   // یک رنگ — بقیه خودکار مشتق می‌شوند
    icon: "✍",
    variant: "کادر",     // نوار | کادر | ساده | برچسب
    collapsible: true,
    counter: true,       // «نکته ۱»، «نکته ۲»
    attrs: [{ name: "نویسنده", type: "متن" }],
  },
};
```

در متن:

```markdown
:::نکته{نویسنده="دفترِ فنی"}
این بند در بازبینی ۱۴۰۴ اضافه شد.
:::
```

⚠️ **مقداری که فاصله دارد باید گیومه بگیرد.** در نحوِ directive، فاصله
پایانِ مقدارِ بی‌گیومه است — `{نویسنده=دفترِ فنی}` به دو صفتِ غلط تبدیل
می‌شود (`نویسنده=دفترِ` و `فنی=`). مقدارِ بی‌فاصله گیومه لازم ندارد.

**فقط یک رنگ بدهید.** پس‌زمینه، حاشیه و رنگِ متن با `color-mix(in oklab, …)`
ساخته می‌شوند تا تمِ روشن و تاریک هر دو خودکار خوانا باشند.

**تگِ `:::` قابلِ تغییر نیست** — نحوِ ثابتِ CommonMark است. نام و صفات
کاملاً آزادند، و **نامِ فارسی کار می‌کند** (`:::نکته{نوع=مؤلف}`).

**مارکِ ناشناخته هرگز خطا نمی‌دهد و حذف نمی‌شود.** خام رندر می‌شود و صفاتش
دست‌نخورده در سند می‌مانند. سندِ شما با نبودنِ یک تعریف نمی‌شکند.

## درخت — یک منبع، دو نما

`buildOutline` تنها سازندهٔ درخت است. هم پنلِ کناری از آن می‌خواند، هم
تاشدنِ داخلِ سند. اگر دو مدلِ جدا بود، روزی از هم واگرا می‌شدند.

```ts
const tree = buildOutline(doc, marks);
// [{ id, kind, level, title, number?, status?, from, to, children }]
```

مارکی در درخت می‌آید که `anchor: true` باشد. «نکته» یادداشت است نه گرهِ
ساختار، پس نمی‌آید.

### تاشدن

```ts
import { foldPlugin, toggleFold, foldAll } from "@tamin/markdown";

foldPlugin({ initial: savedIds, onChange: (ids) => localStorage.setItem(…) });
```

سه قاعده‌ای که رعایت شده و تست دارد:

1. حالتِ تاشدگی **وارد مارک‌داون نمی‌شود** — وگرنه رفت‌وبرگشت می‌شکست.
2. تاکردن **قدمِ undo نمی‌سازد** — تغییرِ سند نیست.
3. مکان‌نما که وارد بخشِ بسته شود، **خودکار باز می‌شود**.

## بلوک‌های سنگین

`features` چهار کلید دارد. **این پیش‌فرض‌ها اندازه‌گیری‌شده‌اند، نه سلیقه‌ای:**

| ویژگی | پیش‌فرض | دلیل |
|---|---|---|
| `math` (KaTeX) | ✅ روشن | سبک است؛ در مرورگر تست شد و رشتهٔ اصلی را قفل نمی‌کند |
| `highlight` (Shiki) | ✅ **روشن** | در Web Worker اجرا می‌شود — پایین |
| `mermaid` | ❌ خاموش | کدِ دلخواه اجرا می‌کند (بندِ ۱۱ امنیت) |
| `html` | `escape` | امن‌ترین حالت |

```tsx
<MarkdownEditor features={{ mermaid: true }} />  // با آگاهی از هزینه‌اش
<MarkdownEditor features={{ highlight: false }} /> // کدِ خام، بی worker
```

**نبودِ هر سه هرگز خطا نمی‌دهد.** بلوک به‌صورتِ کدِ خام نمایش داده می‌شود و
در رفت‌وبرگشت سالم می‌ماند. تست دارد.

### رنگ‌آمیزی در Web Worker

تا نسخهٔ قبل `highlight` **خاموش** بود، و آن هم سلیقه‌ای نبود:
`import("shiki")` در رشتهٔ اصلی صفحه را چند ثانیه بی‌پاسخ می‌کرد — تا
حدی که `page.evaluate` هم timeout می‌خورد. حتی با `langs: []` هم همین
بود، پس مسئله گرامرها نبودند بلکه خودِ بارگذاریِ ماژول.

حالا کلِ رنگ‌آمیزی در **Web Worker** انجام می‌شود، پس رشتهٔ اصلی اصلاً
درگیرِ آن نیست و دلیلِ خاموش‌بودن از بین رفته است.

| سنجه | قبل | بعد |
|---|---|---|
| بیشترین وقفهٔ رشتهٔ اصلی | چند **ثانیه** | زیر ۲۵۰ **میلی‌ثانیه** (تستِ e2e) |
| باندلِ اصلی | — | بی‌تغییر |

★ **تا آمدنِ رنگ، کد خوانا و قابلِ ویرایش است** (`data-highlighted="pending"`).
هیچ‌وقت صفحهٔ خالی یا پرشِ چیدمان دیده نمی‌شود.

★ **زبانِ ناشناخته خطا نیست.** فهرستِ زبان‌ها دستی است
(`core/highlight/langs.ts`) — سیزده زبانِ رایج، به‌علاوهٔ نامِ مستعار
(`ts`، `py`، `yml`، …). زبانِ بیرونِ فهرست خام می‌ماند: خوانا، قابلِ
ویرایش، قابلِ کپی. اضافه‌کردنِ زبان یعنی **یک خط**.

چهار تلهٔ محیطی که در مرورگرِ واقعی اندازه گرفته شدند — و هر کدام باعث
`pending`ِ ابدی می‌شدند **بی هیچ خطایی در کنسول** — در
[تصمیمِ ۰۰۲۴](../../docs/decisions/0024-highlight-web-worker.md) نوشته‌اند.

## خروجیِ PDF

```ts
import { exportPdf } from "@tamin/markdown";
await exportPdf(doc, { title: "بخشنامه", toc: true, pageSize: "A4" });
```

یا فقط `Ctrl+P` / دکمهٔ ⎙ در نوارِ ابزار.

★ **از موتورِ چاپِ خودِ مرورگر استفاده می‌شود، نه کتابخانهٔ PDF.** دلیلِ
اصلی **فارسی** است: کتابخانه‌های PDF باید فونت را جاسازی و شکل‌دهیِ
حروف و راست‌به‌چپ را خودشان انجام دهند، و هیچ‌کدام درست انجام نمی‌دهند.
موتورِ چاپ همان موتوری است که صفحه را رندر کرده.

★ **همان محتوای `exportHtml`** — یک منبعِ حقیقت، پس PDF و HTML هرگز از
هم واگرا نمی‌شوند. همان قواعدِ امنیت هم اعمال می‌شوند.

| گزینه | پیش‌فرض |
|---|---|
| `pageSize` | `A4` |
| `margin` | `2cm 1.8cm` |
| `pageNumbers` | `true` |

CSSِ چاپ این‌ها را رعایت می‌کند: رنگِ کارت‌ها در کاغذ هم می‌آید،
سرفصل تهِ صفحه تنها نمی‌ماند، و کارت و جدول وسطشان صفحه عوض نمی‌شود.

## تمام‌صفحه

`F11` یا دکمهٔ ⤢. **دو حالت، نه یکی:** اول Fullscreen APIِ مرورگر؛ اگر
نبود یا رد شد (`iframe` بی مجوز، سافاریِ iOS)، تمام‌صفحهٔ نرم با
`position: fixed`. از دیدِ کاربر تقریباً همان است و هرگز شکست نمی‌خورد.

★ خروجِ مرورگر از تمام‌صفحه (با `Escape` یا تعویضِ تب) شنیده می‌شود، پس
دکمه هیچ‌وقت «خروج» نمی‌گوید در حالی که صفحه عادی است.

## تصویر

خمیرکردن (`Ctrl+V`) یا رهاکردنِ فایل روی متن.

```tsx
// پیش‌فرض: بی هیچ تنظیمی کار می‌کند — تصویر `data:` می‌شود.
<MarkdownEditor />

// یا آپلود کن و فقط نشانی را نگه دار:
<MarkdownEditor images={{ onUploadImage: async (f) => upload(f), maxBytes: 2e6 }} />
```

★ **با آپلودکننده، جای‌گیرِ موقت فوراً دیده می‌شود.** کاربر نباید به
صفحهٔ خالی نگاه کند و حدس بزند چیزی شد یا نه.

★ **آپلودِ شکست‌خورده سند را خراب نمی‌کند** — جای‌گیر برداشته می‌شود، متنِ
اصلی دست‌نخورده می‌ماند، و پیام به کاربر نشان داده می‌شود.

★ **سقفِ پیش‌فرض ۵ مگابایت.** بی سقف، خمیرکردنِ یک عکسِ بزرگ به `data:`
مرورگر را می‌خواباند.

⚠️ در نشانیِ `data:` دونقطه escape می‌شود (`data\:image`). این درست
است نه باگ — `:` در نحوِ directive معنی دارد، و CommonMark این escape
را می‌فهمد. رفت‌وبرگشت سالم می‌ماند و تست دارد.

## پیش‌نمایشِ زنده

نشانه‌های مارک‌داون فقط وقتی دیده می‌شوند که مکان‌نما داخلِ همان بلوک باشد.
بیرون که رفت، پنهان می‌شوند و متنِ رندرشده می‌ماند.

**نشانه‌ها هرگز وارد سند نمی‌شوند** — `Decoration.widget` روی لایهٔ نمایش‌اند.
پس `serialize` دست‌نخورده می‌ماند و کپی‌کردنِ متن `**` نمی‌گیرد.

هر پنج حالتِ لبه‌ای تست شده:

| حالت | رفتار |
|---|---|
| انتخابِ چندبلوکی | هیچ بلوکی نشانه نشان نمی‌دهد (صفحه نمی‌لرزد) |
| گره‌های تودرتو | تأکید داخلِ لینک داخلِ عنوان، با ترتیبِ درست |
| پرشِ چیدمان | نشانه‌ها `position: absolute`اند |
| کلیک روی متن | widget با `ignoreSelection` |
| undo | نشانه در تاریخچه نمی‌آید |

## جدول

از GFM خوانده می‌شود و با `prosemirror-tables` ویرایش می‌شود: انتخابِ
سلول، کشیدنِ مرزها، `Tab` برای سلولِ بعدی.

```ts
import { insertTable, addRowAfter, setColumnAlign } from "@tamin/markdown";
insertTable(3, 3)(view.state, view.dispatch);
```

⚠️ **جدول تنها جایی است که خروجی عیناً ورودی نیست.** remark ردیفِ
جداکننده را به کمینه‌اش نرمال می‌کند (`| --- |` → `| - |`). محتوا و تراز
کاملاً حفظ می‌شوند، و شکلِ نرمال‌شده **پایدار** است: بارِ دوم دیگر عوض
نمی‌شود. تست دارد.

## سریالایزر — انتخاب‌های ثابت

جاهایی که مارک‌داون چند نوشتنِ معادل دارد، نشانهٔ **خودِ کاربر** حفظ می‌شود
(`**` یا `__`، `-` یا `*`). فقط برای بلوکِ تازه‌ساخته پیش‌فرض به کار می‌رود:

| چیز | پیش‌فرض |
|---|---|
| فهرست | `-` |
| تأکید / پررنگ | `*` / `**` |
| بلوکِ کد | `` ``` `` |
| جداکننده | `---` |
| تورفتگیِ آیتم | `one` |
| صفاتِ directive | بی‌گیومه |

## منوی `/`

`/` در ابتدای بلوک یا بعد از فاصله، منوی درج را باز می‌کند. با تایپ فیلتر
می‌شود، با کلیدهای جهت انتخاب و با `Enter` درج.

★ **مارک‌های سفارشی خودکار در منو می‌آیند.** کاربری که مارکِ «تعریف»
می‌سازد، بلافاصله `/تعریف` دارد — صفر خطِ کدِ جدید. این همان معنیِ عملیِ
«مکانیزم عمومی است».

`/` وسطِ کلمه منو را باز نمی‌کند (وگرنه هر نشانیِ اینترنتی بازش می‌کرد)، و
داخلِ بلوکِ کد هم غیرفعال است.

## خروجیِ HTML

```ts
import { exportHtml } from "@tamin/markdown";

const html = exportHtml(doc, { title: "بخشنامه", toc: true });
```

فایلِ خروجی **مستقل** است: CSS درون‌خطی، بی هیچ وابستگی، با تمِ تاریک و
استایلِ چاپ. در مرورگر تست شده که واقعاً خودکفا رندر می‌شود.

★ **همان قواعدِ امنیت اینجا هم اعمال می‌شوند** — خروجیِ HTML جایی است که
XSS واقعاً خطرناک می‌شود، چون فایل ممکن است دستِ کسِ دیگری برود. تست
دارد که `<script>` در فایلِ صادرشده اجرا نمی‌شود.

★ **لنگرها حفظ می‌شوند**، پس ارجاع‌های `#fasl-4` بینِ فایل‌های صادرشده هم
کار می‌کنند. سرفصلِ بی‌لنگر، لنگرِ خودکار می‌گیرد تا فهرستِ مطالب به جای
درست اشاره کند.

| گزینه | پیش‌فرض |
|---|---|
| `standalone` | `true` — سندِ کامل با `<head>` |
| `html` | `escape` |
| `toc` | `false` |
| `dir` / `lang` | `rtl` / `fa` |
| `css` | CSSِ پیش‌فرض (قابلِ جایگزینی) |

## حالت‌های نوشتن

```tsx
<MarkdownEditor focusMode typewriterMode />
```

- **تمرکز:** بلوکِ فعال پررنگ، بقیه کم‌رنگ (`opacity: .35`).
- **ماشین‌تحریر:** خطِ فعال همیشه وسطِ صفحه می‌ماند.

هر دو فقط **نمایش**اند — نه سند عوض می‌شود نه تاریخچه، مثلِ تاشدن.
`prefers-reduced-motion` رعایت می‌شود.

## فوت‌نوت

نحوِ GFM: `متن[^۱]` و `[^۱]: توضیح`. **شناسهٔ فارسی کار می‌کند** — هم عدد
(`[^۱]`) هم متن (`[^منبع]`).

ارجاعِ بی‌تعریف سند را نمی‌شکند؛ چون بی تعریف اصلاً فوت‌نوت نیست و
متنِ عادی می‌ماند.

## جست‌وجو

`Ctrl+F` برای جست‌وجو، `Ctrl+H` برای جایگزینی. گزینه‌ها: بزرگ/کوچک،
کلمهٔ کامل، regex، و **یک‌سان‌سازیِ فارسی** (پیش‌فرض روشن).

★ **جست‌وجو روی سند است، نه DOM.** پس متنِ داخلِ بخشِ تاشده هم پیدا
می‌شود، و رفتن به آن، بخش را خودکار باز می‌کند. جست‌وجوی DOM فقط چیزی را
می‌دید که *دیده* می‌شود.

★ **یک‌سان‌سازیِ فارسی:** «كتاب» با کافِ عربی و «کتاب» فارسی یکی‌اند؛
«۵۰» و «50» هم. کاربر «کتاب» تایپ می‌کند و انتظار دارد سندی که از Word
آمده و کافِ عربی دارد را پیدا کند.

★ **جایگزینیِ همه = یک قدمِ undo.** کاربری که ۴۰ جا را عوض کرده و پشیمان
شده، نباید ۴۰ بار `Ctrl+Z` بزند. تست دارد — هم واحد هم در مرورگر.

۹۰ بلوکِ کد، ۳۰ جدول و ۹۰ تصویر.

```bash
pnpm --filter @tamin/markdown bench
```

## امنیت

اسنادِ این پروژه از فایلِ Word وارد می‌شوند — یعنی محتوا لزوماً مالِ خودتان
نیست. **پیش‌فرض همیشه امن است.**

| چیز | رفتار |
|---|---|
| HTMLِ خام | `escape` — به‌صورتِ متن، نه رندرشده |
| `javascript:` در لینک | مسدود → `#blocked` |
| `data:` در `href` | مسدود (`data:image/*` در `src` مجاز) |
| `on*` در HTML | حذف |
| لینکِ خارجی | `rel="noopener noreferrer"` |
| Mermaid | `securityLevel: "strict"` + پیش‌فرض خاموش |

```tsx
// رندرِ HTML — فقط وقتی محتوا مالِ خودتان است:
<MarkdownEditor features={{ html: "sanitize" }} />  // فهرستِ سفید
<MarkdownEditor features={{ html: "raw" }} />       // بی‌فیلتر
```

نشانیِ ناامن **از سند حذف نمی‌شود** — فقط رندر نمی‌شود. اگر حذفش کنیم،
محتوای کاربر بی‌صدا عوض می‌شود.

سه ترفندی که تست شده‌اند و رد می‌شوند: `JavaScript:` با حروفِ بزرگ،
`java	script:` با کاراکترِ کنترلی، و `<div><img onerror>` که با حذفِ
`div` به سطحِ بالا می‌آمد.

## فارسی

- نیم‌فاصله (ZWNJ) در رفت‌وبرگشت گم نمی‌شود — تست دارد.
- لنگر از متنِ فارسی ساخته می‌شود و خوانا می‌ماند: `فصل-چهارم`.
- «كتاب» عربی و «کتاب» فارسی یک لنگر می‌گیرند.
- ارقامِ فارسی در لنگر به انگلیسی نگاشت می‌شوند: `ماده ۵۰` → `ماده-50`.
- بلوکِ کد همیشه LTR است، حتی در سندِ RTL.
- **شمارشِ کلمه نیم‌فاصله را مرزِ کلمه نمی‌شمارد** — «می‌شود» یک کلمه است.
  با `split(/\s+/)` متنِ فارسی حدودِ ۲۰٪ بیشتر شمرده می‌شد.

## توسعه

```bash
pnpm --filter @tamin/markdown test
```

```bash
pnpm --filter @tamin/markdown build
```

تستِ سرتاسری (سرورِ `apps/web` باید بالا باشد):

```bash
npx playwright test
```

⚠️ **سه تلهٔ محیطی که وقت می‌گیرند:**

۱. **هر بار پکیج را عوض کنی، `pnpm --filter @tamin/markdown build` لازم
   است** تا در مرورگر دیده شود.

۲. **سرورِ قدیمی را بکش، وگرنه بیلدِ کهنه را سرو می‌کند.** این بارها
   باعث شد ساعت‌ها دنبالِ باگی بگردیم که وجود نداشت. برای بیلدِ تولیدی:

   ```bash
   pnpm --filter @tamin/markdown build && pnpm --filter web build
   ```

   و بعد سرور را **از نو** بالا بیاور.

۳. **در Vitest، تستِ async + jsdom + `EditorView` با NodeViewِ نامتقارن
   قفل می‌شود** (۹۰ ثانیه). تست‌های NodeView عمداً همگام‌اند —
   `tests/unit/node-views.test.ts` توضیحش را دارد.

۴. **ناوبری با کلید در سندِ نمونه غیرقابلِ اتکاست** — از
   `placeCursorInParagraph` در فایلِ e2e استفاده شود، یا از بلوکِ
   آماده‌ای که در سند هست.

بازسازیِ تم‌های Shiki (فقط اگر نسخهٔ Shiki عوض شود):

```bash
node packages/markdown/scripts/vendor-themes.mjs
```

`core/` هرگز React را import نمی‌کند و `viewer` هرگز ProseMirror را — هر دو
با تست اجبار می‌شوند (`tests/unit/architecture.test.ts`).
