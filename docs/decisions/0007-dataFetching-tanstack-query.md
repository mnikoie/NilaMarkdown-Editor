# 0007 — دادهٔ سمتِ کلاینت: TanStack Query

- **تاریخ:** ۱۴۰۵/۵/۲۹
- **وضعیت:** ✅ پذیرفته‌شده

## زمینه

گرفتنِ داده از سرور چطور مدیریت شود؟

## تصمیم

**TanStack Query** انتخاب شد.

دلیل‌ها:
- بارگذاری و خطا و تلاشِ دوباره را خودش مدیریت می‌کند
- کشِ هوشمند — دادهٔ کهنه را خودش تازه می‌کند
- ابزارِ عیب‌یابیِ خوب

عیب‌هایی که پذیرفته شد:
- برای یکی دو درخواستِ ساده زیادی است
- مفهومش (کش و کلید) اول کمی گیج‌کننده است

## گزینه‌های دیگر

| گزینه | مزیت | چرا انتخاب نشد |
|---|---|---|
| SWR | کوچک و ساده | امکاناتش از TanStack Query کمتر است؛ برای کارِ پیچیده‌تر کم می‌آورد |

## پیامدها

- فایل‌ها و وابستگی‌هایی که این تصمیم اضافه کرد، در همان کامیتِ این تصمیم‌اند.
- برگشت از این تصمیم با `git revert` همان کامیت انجام می‌شود — دقیقاً همان
  تغییرها پس گرفته می‌شوند، نه بیشتر و نه کمتر.
- `project.config.json` فقط **قصد** را ثبت می‌کند. نصب‌بودنِ واقعی جدا و با
  مدرک بررسی می‌شود (لینکِ node_modules، خروجیِ docker compose ps، وجودِ .venv).
