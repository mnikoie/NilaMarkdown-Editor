# ۰۰۲۶ — تایپوگرافیِ متنِ سند و آیکونِ نوارِ ابزار

وضعیت: پذیرفته‌شده — ۳۱ مرداد ۱۴۰۵

## مسئله

کاربر به ویرایشگر نگاه کرد و گفت «افتضاح است». حق داشت. با اینکه ۳۰۶
تستِ واحد و ۲۹ تستِ سرتاسری سبز بودند، **در مرورگر** این‌ها دیده شد:

| چیز | وضعیت |
|---|---|
| `h1` | اندازه ۱۶px، وزن ۴۰۰ — **دقیقاً مثلِ پاراگراف** |
| `ul` / `ol` | `list-style: none`، تورفتگی صفر |
| چک‌لیست | بی مربع، فقط متن |
| `blockquote` | بی هیچ حاشیه‌ای |
| ریاضی | هر فرمول **دوبار** چاپ می‌شد |
| نوارِ ابزار | ردیفی از گلیفِ نامفهوم (`{}`، `⤢`، `⎙`) |

## چرا تست‌ها این را نگرفتند

هر شش مورد از دیدِ تست‌های موجود **نامرئی** بودند، و این نکتهٔ اصلیِ
این سند است:

تست‌ها **ساختار** را می‌سنجیدند — «آیا گرهٔ `h1` ساخته شد؟» — و جواب
همیشه بله بود. گره **بود**، فقط بی‌استایل بود. هیچ تستی مقدارِ
محاسبه‌شدهٔ CSS را نمی‌خواند.

درسش: برای چیزی که کاربر **می‌بیند**، تستِ ساختاری کافی نیست. باید
`getComputedStyle` سنجیده شود. `tests/e2e/typography.spec.ts` دقیقاً
همین کار را می‌کند.

## ریشهٔ مشترک

بالای `src/styles/index.css` نوشته شده بود که `preflight.css` عمداً
وارد نمی‌شود، چون ریستِ Tailwind اگر منتشر شود استایلِ صفحهٔ میزبان را
خراب می‌کند.

**آن تصمیم درست بود و سرِ جایش می‌ماند.** ولی نتیجهٔ ناخواسته‌اش این بود
که کسی جایش را پر نکرد: مرورگر هم پیش‌فرضِ خودش را نمی‌گذارد، چون
`theme.css` آن را خنثی می‌کند.

## تصمیم

استایلِ عناصرِ پایه نوشته شد، ولی **همه با پیشوندِ `.tm-editor`** — پس
بیرونِ ویرایشگر هیچ اثری ندارند. همان نگرانی‌ای که preflight را رد کرد،
اینجا رعایت شده، و یک تستِ e2e (`استایل‌ها از ویرایشگر بیرون نمی‌زنند`)
آن را تضمین می‌کند.

## سه نکتهٔ ریز

★ **`list-style-type: persian`** — سندِ فارسی با `1.` و `2.` شروع
نمی‌شود. CSS این مقدار را از پیش دارد؛ هیچ جاوااسکریپتی لازم نیست. فقط
وقتی اعمال می‌شود که `dir="rtl"` باشد.

★ **MathML با `clip` مخفی می‌شود، نه `display: none`** — KaTeX دو
خروجی می‌سازد: دیداری و MathMLِ صفحه‌خوان. با `display: none`
صفحه‌خوان هم آن را از دست می‌داد.

★ **CSSِ KaTeX جدا ماند.** جاسازی‌اش در `styles.css` یعنی کسی که ریاضی
نمی‌خواهد هم ~۲۵ کیلوبایت و فونت‌ها را دانلود کند. حالا در README
مستند است، و تستِ e2e می‌گیرد اگر مصرف‌کننده فراموشش کند.

## آیکون‌ها: `lucide-react`

گلیف‌های متنی دو مشکل داشتند: نامفهوم بودند، و رندرشان به فونتِ سیستم
بستگی داشت پس روی هر دستگاه شکلِ دیگری می‌گرفتند.

`lucide-react` **peerDependencyِ اختیاری** است و `external` هم هست، پس:
- به کسی تحمیل نمی‌شود،
- از باندلِ مصرف‌کننده می‌آید نه از ما (وگرنه دو نسخه دانلود می‌شد)،
- tree-shakable است، پس فقط همان هجده آیکون می‌روند.

**این تصمیمِ کاربر بود، نه انتخابِ خودسرانه** — طبقِ قاعدهٔ `CLAUDE.md`
که می‌گوید تکنولوژی را باید کاربر انتخاب کند.
