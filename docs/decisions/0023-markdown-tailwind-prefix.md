# 0023 — استایلِ پکیجِ مارک‌داون: Tailwind 4 با پیشوندِ `tm:` و بی preflight

- **تاریخ:** ۱۴۰۵/۵/۳۰
- **وضعیت:** ✅ پذیرفته‌شده

## زمینه

`@tamin/markdown` قرار است پکیجی باشد که در `apps/web` (و شاید جاهای دیگر)
نصب می‌شود. مصرف‌کننده خودش Tailwind 4 دارد. دو خطر:

۱. تصادمِ نامِ کلاس‌ها با Tailwindِ مصرف‌کننده.
۲. منتشرشدنِ ریست (preflight) که استایلِ کلِ صفحهٔ میزبان را خراب می‌کند.

## تصمیم

داخلِ پکیج با Tailwind 4 نوشته می‌شود و بیلد یک `dist/styles.css`ِ
کامپایل‌شده می‌سازد. مصرف‌کننده فقط `import "@tamin/markdown/styles.css"`
می‌کند و **لازم نیست Tailwind داشته باشد**.

```css
@layer theme, components, utilities;
@import "tailwindcss/theme.css"     layer(theme)     prefix(tm);
@import "tailwindcss/utilities.css" layer(utilities) prefix(tm);
/* preflight.css عمداً نیست */
```

### دو چیزی که با کامپایلِ واقعی تأیید شد

روی همان `tailwindcss@4.3.3`ِ نصب‌شده تست شد، نه از روی حافظه:

۱. **پیشوند در نسخهٔ ۴ با `:` است نه `-`.** خروجی `.tm\:flex` می‌شود، پس در
   کد `class="tm:flex"` نوشته می‌شود. این با انتظارِ `tm-`ِ PROMPT.md فرق
   دارد؛ PROMPT برای نسخهٔ ۳ نوشته شده بود. کلاسِ بی‌پیشوند اصلاً تولید
   نمی‌شود — یعنی جداسازی تضمین است.

۲. **preflight حذف می‌شود** با واردکردنِ فقط دو لایه به‌جای کلِ
   `tailwindcss`. تست: `box-sizing:border-box` در خروجی نیست.

### رنگ‌ها: یک رنگِ پایه، نه شش رنگ

کاربر برای مارکِ سفارشی **یک** رنگ می‌دهد. پس‌زمینه و حاشیه و رنگِ متن با
`color-mix(in oklab, …)` مشتق می‌شوند.

دلیل: اگر شش رنگ از کاربر بگیریم، در تمِ تاریک ترکیبِ ناخوانا می‌سازد. با یک
رنگ، هر دو تم خودکار درست درمی‌آیند. `in oklab` و نه `in srgb` — چون در srgb
ترکیبِ رنگ‌های اشباع خاکستریِ گل‌آلود می‌دهد.

## گزینه‌های دیگر

| گزینه | مزیت | چرا انتخاب نشد |
|---|---|---|
| CSS خام بی Tailwind | بی وابستگیِ بیلد | نوشتنش کندتر؛ توکن‌های آماده از دست می‌رود |
| CSS Modules | جداسازیِ خودکار | نامِ کلاس‌ها هش می‌شوند و مصرف‌کننده نمی‌تواند override کند |
| Tailwind بی پیشوند | ساده‌تر | تصادم با Tailwindِ مصرف‌کننده — همان چیزی که می‌خواستیم جلویش را بگیریم |
| `styled-components` یا CSS-in-JS | داینامیک | حجمِ اجرا در زمانِ رندر؛ با بودجهٔ ۴۰ کیلوبایتِ viewer نمی‌خواند |

## پیامدها

- `tailwindcss` و `@tailwindcss/cli` به devDependenciesِ `packages/markdown`
  اضافه شدند. در ریشه نصب بودن کافی نیست: pnpm سخت‌گیر است و هر پکیج فقط
  چیزی را می‌تواند import کند که در `package.json` خودش نوشته باشد. (دوباره
  دانلود نمی‌شود؛ از همان انبارِ مشترک لینک می‌خورد.)
- اسکریپتِ بیلد دو مرحله شد: `tsup && tailwindcss -i … -o dist/styles.css`.
- همهٔ رنگ‌ها متغیرِ CSS‌اند. یک تست این را اجبار می‌کند: هیچ رنگِ hex در
  فایل‌های TS نباشد (جز `builtin.ts` که رنگِ پایهٔ مارک‌های پیش‌فرض است).
- حجمِ خروجی: `styles.css` = ۱٫۵ کیلوبایتِ gzip.
