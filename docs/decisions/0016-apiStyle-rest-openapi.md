# 0016 — سبکِ API: REST + OpenAPI

- **تاریخ:** ۱۴۰۵/۵/۲۹
- **وضعیت:** ✅ پذیرفته‌شده

## زمینه

برنامه و سرور با چه قراردادی حرف بزنند؟

## تصمیم

**REST + OpenAPI** انتخاب شد.

دلیل‌ها:
- همه‌جا فهمیده می‌شود — هر زبانی کلاینتش را می‌سازد
- سند از خودِ قرارداد می‌آید
- کش و پراکسی و ابزارهای HTTP همه با آن راحت‌اند

عیب‌هایی که پذیرفته شد:
- برای دادهٔ تودرتو چند رفت‌وبرگشت لازم می‌شود
- هماهنگ نگه‌داشتنِ سند با کد دستی است

## گزینه‌های دیگر

| گزینه | مزیت | چرا انتخاب نشد |
|---|---|---|
| tRPC | نوعِ داده بی هیچ تولیدِ کدی از سرور به کلاینت می‌رسد | فقط در دنیای TypeScript کار می‌کند؛ کلاینتِ غیرِ TS باید REST جدا داشته باشد |
| GraphQL | کلاینت دقیقاً همان چیزی را می‌گیرد که خواسته | کش‌کردن سخت‌تر از REST است؛ پیچیدگیِ اضافه برای APIِ ساده |

## پیامدها

- فایل‌ها و وابستگی‌هایی که این تصمیم اضافه کرد، در همان کامیتِ این تصمیم‌اند.
- برگشت از این تصمیم با `git revert` همان کامیت انجام می‌شود — دقیقاً همان
  تغییرها پس گرفته می‌شوند، نه بیشتر و نه کمتر.
- `project.config.json` فقط **قصد** را ثبت می‌کند. نصب‌بودنِ واقعی جدا و با
  مدرک بررسی می‌شود (لینکِ node_modules، خروجیِ docker compose ps، وجودِ .venv).
