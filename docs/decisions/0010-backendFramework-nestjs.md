# 0010 — فریم‌ورکِ بک‌اند: NestJS

- **تاریخ:** ۱۴۰۵/۵/۲۹
- **وضعیت:** ✅ پذیرفته‌شده

## زمینه

API با چه چیزی نوشته شود؟

## تصمیم

**NestJS** انتخاب شد.

دلیل‌ها:
- ساختارِ آماده (ماژول، تزریقِ وابستگی)
- برای تیم و پروژهٔ بزرگ مناسب
- مستنداتِ خوب

عیب‌هایی که پذیرفته شد:
- برای کارِ کوچک زیادی است
- مفاهیمِ بیشتری برای یادگیری

## گزینه‌های دیگر

| گزینه | مزیت | چرا انتخاب نشد |
|---|---|---|
| Express | سبک و ساده | ساختار را خودت باید بسازی؛ در پروژهٔ بزرگ بی‌نظم می‌شود |
| Fastify | از Express سریع‌تر است | جامعهٔ کوچک‌تر از Express؛ میان‌افزارهای Express همیشه مستقیم کار نمی‌کنند |

## پیامدها

- فایل‌ها و وابستگی‌هایی که این تصمیم اضافه کرد، در همان کامیتِ این تصمیم‌اند.
- برگشت از این تصمیم با `git revert` همان کامیت انجام می‌شود — دقیقاً همان
  تغییرها پس گرفته می‌شوند، نه بیشتر و نه کمتر.
- `project.config.json` فقط **قصد** را ثبت می‌کند. نصب‌بودنِ واقعی جدا و با
  مدرک بررسی می‌شود (لینکِ node_modules، خروجیِ docker compose ps، وجودِ .venv).
