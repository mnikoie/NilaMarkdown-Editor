# ۰۰۲۹ — زبان و جهتِ متن، و سیاستِ یکپارچهٔ تاشدن

- **تاریخ:** ۱۴۰۵/۰۵/۳۰
- **وضعیت:** پذیرفته‌شده

## زمینه

ویرایشگر هم رابطِ فارسی دارد و هم ممکن است در نرم‌افزارِ انگلیسی استفاده
شود. خودِ سند نیز می‌تواند فارسی و انگلیسی را بلوک‌به‌بلوک مخلوط کند؛ پس
یک `dir` برای کلِ ویرایشگر برای متن کافی نیست. هم‌زمان سه سازوکارِ تاشدن
وجود دارد: فصل‌ها و عنوان‌ها، فهرست‌های تودرتو، و کارت‌های directive.
رفتارِ متفاوتِ این سه، فلش‌هایی می‌ساخت که ظاهراً یک کار می‌کردند اما
پیش‌فرض و قواعدِ متفاوت داشتند.

## تصمیم

### ۱. زبانِ رابط از جهتِ محتوای سند جدا است

`MarkdownEditor` یک `locale` با مقادیرِ `fa` و `en` دارد. این مقدار متنِ
کنترل‌ها، `lang` و جهتِ پوسته را تعیین می‌کند. ترجمه‌ها در یک context کوچک
و داخلی نگه داشته می‌شوند و منوها و popoverهای exportشده نیز از همان
context می‌خوانند. افزودنِ کتابخانهٔ i18n برای دو زبان، وابستگی و API تازه‌ای
تحمیل می‌کرد و پذیرفته نشد.

در `dir="auto"`، هر textblock با اولین نویسهٔ قویِ حرفی تشخیص داده می‌شود:
عربی/فارسی/عبری `rtl` و لاتین/سیریلیک/یونانی `ltr`. عدد و علامت جهت را
تعیین نمی‌کنند. صفتِ `dir` با `Decoration.node` به DOM می‌رود و واردِ مدلِ
ProseMirror یا Markdown نمی‌شود. بنابراین تغییرِ زبان یا جهت، رفت‌وبرگشتِ
سند و تاریخچهٔ undo را عوض نمی‌کند.

### ۲. یک تنظیمِ عمومی برای هر سه نوعِ تاشدن

API عمومیِ `folding` دو انتخاب دارد:

| گزینه | مقدارها | پیش‌فرض |
|---|---|---|
| `initial` | `collapsed` / `expanded` | `collapsed` |
| `mode` | `accordion` / `multiple` | `accordion` |

پیش‌فرضِ کامپوننت این است که در اجرای اول همهٔ عنوان‌ها، والدهای فهرست و
کارت‌ها بسته باشند. در حالتِ آکاردئون، بازکردنِ یک گره فقط خواهر/برادرهای
هم‌سطح و دارای همان والد را می‌بندد؛ والد یا فرزندِ باز بی‌دلیل بسته
نمی‌شود. فرمان‌های «بستن همه» و «بازکردن همه» صریح‌اند و از محدودیتِ
آکاردئون عبور می‌کنند.

سه پیاده‌سازی یکی نشده‌اند: عنوان‌ها به موقعیت‌های سراسری و Outline وابسته‌اند،
فهرست‌ها با موقعیتِ list item کار می‌کنند، و کارت‌ها NodeView هستند. آن‌ها
فقط قرارداد و تنظیمِ مشترک دارند. یکی‌کردنِ ذخیرهٔ حالت، وابستگیِ نامناسب
میان core و NodeView می‌ساخت.

وقتی کاربر گره‌ای را می‌بندد که مکان‌نما داخلِ محتوای آن است، ابتدا selection
به خودِ والد منتقل می‌شود. بدون این کار، قاعدهٔ ایمنیِ «محتوای دارای مکان‌نما
را پنهان نکن» درست عمل می‌کرد ولی از دیدِ کاربر فلش هیچ کاری نمی‌کرد.

### ۳. گزینه‌ها در View و رفتارهای وابسته

منوی `View` زبانِ رابط، باز/بسته‌کردنِ همه، شروعِ بسته/باز، و حالتِ
آکاردئون/چندباز را نشان می‌دهد. این گزینه‌ها متعلق به تجربهٔ ویرایشگرند؛
ذخیرهٔ دائمیِ ترجیح همچنان وظیفهٔ میزبان است و از callbackها انجام می‌شود.

ناوبریِ Outline پس از تغییرِ selection، گرهٔ واقعیِ متن را نیز با
`scrollIntoView` به مرکزِ دید می‌آورد؛ این رفتار در Focus Mode نیز برقرار
است. پنلِ جست‌وجو داخلِ ظرفِ sticky کنترل‌ها قرار می‌گیرد تا هنگامِ پیمایش
محو یا زیرِ toolbar پنهان نشود.

زمانِ مطالعه با سرعتِ قابل‌تنظیمِ `readingWordsPerMinute` محاسبه می‌شود؛
پیش‌فرض ۲۵۰ کلمه در دقیقه است و زمان‌های بیش از ۶۰ دقیقه به صورتِ ساعت و
دقیقه نمایش داده می‌شوند، نه یک عددِ مبهمِ بزرگ.

## گزینه‌های ردشده

| گزینه | چرا رد شد |
|---|---|
| یک جهت برای کل سند | پاراگرافِ انگلیسی در سندِ فارسی و برعکس نادرست می‌شد |
| ذخیرهٔ `dir` در Markdown | حالتِ نمایشی را وارد سند و رفت‌وبرگشت را آلوده می‌کرد |
| تشخیص جهت از هر نویسه، شامل عدد | سندی که با شماره شروع می‌شود جهتِ اشتباه می‌گرفت |
| کتابخانهٔ i18n | برای دو زبان وابستگی و سطح API اضافه می‌کرد |
| یک state مشترک برای هر سه fold | مرزِ core، plugin و NodeView را مخلوط می‌کرد |
| آکاردئونِ سراسری | بازکردنِ یک تبصره می‌توانست فصلِ نامرتبط را ببندد |
| نادیده‌گرفتنِ selection هنگام fold | پنهان‌کردنِ مکان‌نما رفتارِ ProseMirror را ناپایدار می‌کرد |

## پیامدها

- رابط فارسی و انگلیسی با `lang` و `dir` درست در دسترس است و محتوای مخلوط
  جهتِ بلوکی دارد.
- تغییرِ جهت و تاشدن هیچ نشانه‌ای به Markdown اضافه نمی‌کند.
- میزبان می‌تواند پیش‌فرضِ تاشدن، حالتِ آکاردئون و سرعتِ مطالعه را تنظیم
  و ترجیحِ کاربر را بیرون از کامپوننت ذخیره کند.
- ترجمهٔ زبانِ سوم نیازمند گسترشِ نوعِ locale و واژه‌نامه است؛ API فعلی
  عمداً ادعای زبانِ دلخواه ندارد.
- هر قابلیتِ fold تازه باید قراردادِ `initial` و `mode` را رعایت کند، حتی
  اگر state داخلیِ مستقل داشته باشد.
